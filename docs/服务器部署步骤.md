# 服务器部署步骤（拿到一台装好 Docker 的 Linux 服务器后照着做）

> 前提：服务器已装 Docker。检查方式（下面第 0 步会做）：
> `docker -v` 能出版本号、`docker compose version` 能出版本号（要有 Compose V2）。

## 先花一分钟理解：Docker 部署到底是什么

**不用手动打镜像传上去。** 部署的本质是三句话：

1. 这个项目 = 3 个容器：**MySQL 数据库** + **建表任务**（跑完自动退出）+ **Next.js 应用**。`docker-compose.yml` 就是把这三个的启动顺序、依赖关系、数据持久化都编排好的一份"剧本"。
2. 剧本里写的是 `build:`（怎么构建），所以只要**把代码弄到服务器上、执行一条命令**，Docker 会自动：拉 MySQL 镜像 → 用代码构建应用镜像 → 按顺序起容器。镜像是在服务器上现构建的。
3. 数据（数据库内容、上传的文件）存在 Docker **卷**里，容器重启、重建、升级都不丢；只有 `docker compose down -v` 才会清空。

> 什么时候才需要"本地打镜像传上去"（`docker save` / 推镜像仓库）？
> 只有服务器**不能联网**或构建依赖太慢时。你们服务器能联网就走上面的正常路线，简单得多。

## 具体步骤

### 0. 上服务器先检查环境

```bash
docker -v                     # 有版本号即可
docker compose version        # 必须是 v2（v2.x.x）
```

如果第二条报错说没有 compose，让同事装一下 `docker-compose-plugin`，其他都不用动。

### 1. 把代码弄上去（二选一）

```bash
# 方式 A：有 git 仓库（推荐，以后更新方便）
git clone <你的仓库地址> /opt/multi-document

# 方式 B：本地打包拷贝（没有远程仓库时）
# 本机执行（Git Bash），排除掉编译产物，包会很小：
cd /d/MyCode && tar --exclude='Multi-document/node_modules' --exclude='Multi-document/.next*' \
  -czf multi-document.tar.gz Multi-document
# 然后传到服务器：
scp multi-document.tar.gz user@服务器IP:/opt/
# 服务器上解压：
cd /opt && tar -xzf multi-document.tar.gz && cd Multi-document
```

### 2. 建配置文件 `.env`（compose 同目录）

```bash
cd /opt/multi-document
cat > .env << 'EOF'
MYSQL_PASSWORD=换成你的数据库密码
ADMIN_AUTH_SECRET=换成一段随机长字符串
EOF
# 随机串可以这样生成：openssl rand -hex 32
```

**为什么要改这两个**：`ADMIN_AUTH_SECRET` 是登录会话的签名密钥，用默认值等于登录凭证可被伪造；数据库密码同理。其余配置都有合理默认值，不用动。

### 3. 一键启动（就这一条命令）

```bash
docker compose up -d --build
```

首次会拉 MySQL 镜像 + npm 装依赖 + Next 构建，**约 5-10 分钟**，属于正常。启动顺序是自动的：db 健康检查通过 → 建表（migrate，跑完退出）→ 灌演示数据（seed，跑完退出）→ 应用启动。

### 4. 验证

```bash
docker compose ps
# 期望：db 是 healthy / running，migrate、seed 是 Exited (0)，app 是 running

curl -I http://localhost:4000        # 期望 HTTP/1.1 200
docker compose logs -f app           # 看应用日志，Ctrl+C 退出
```

浏览器访问（记得在云服务器**安全组/防火墙放开 4000 端口**）：

| 入口 | 地址 | 初始账号 |
|---|---|---|
| 前台 | http://服务器IP:4000 | — |
| 后台 | http://服务器IP:4000/admin | admin / admin123 |

**登录后第一件事：改掉 admin 和 operator 的默认密码。**

> 默认会灌入"中广云 + 大数据"演示数据（开箱即看）。客户环境不想要演示数据的话，在 `.env` 加一行 `SEED_DEMO=false` 再 `docker compose up -d`，得到纯空库。

### 5. 日常运维（记这四条就够了）

```bash
docker compose up -d                 # 服务器重启后 / 日常启动（自动补跑新迁移）
docker compose logs -f app           # 应用日志
docker compose down                  # 停止（数据保留，放心执行）
docker compose up -d --build         # 更新代码后：重新构建并滚动重启
```

数据备份（升级或迁移前做一次）：

```bash
docker compose exec db sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" multi_document' > backup-$(date +%F).sql
```

## 常见坑

- **端口被占**：compose 把应用映射在宿主 4000；如果 4000 被占，改 `docker-compose.yml` 里 app 的 `"4000:4000"` 左边那个数字。
- **想用 80 端口直接访问**：不要硬改应用端口，建议服务器上装个 nginx 反代 80 → 4000（或运维帮忙配）。
- **构建很慢/卡在 npm**：服务器访问 npm 慢的话，是网络问题不是配置问题，可让同事配 npm/镜像源；实在不行再走"本地 build + docker save 传镜像"的路线。
- **`docker compose down -v`** 会连数据卷一起删——等于清库重来，确认清楚再执行。
