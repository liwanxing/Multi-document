# 启动说明（一页纸）

## 一键启动（推荐）

Git Bash 里执行：

```bash
cd /d/MyCode/Multi-document
bash scripts/dev-start.sh
```

它会自动依次完成：检查 Docker → 启动数据库容器 → 等数据库就绪 → 启动开发服务器。
看到 `Ready` 后访问 http://localhost:4000 。首次编译约 1 分钟，属正常；之后改代码秒级热更新。

## 手动启动（三步）

```bash
# 1. Docker Desktop 必须运行（重启电脑后常需手动开，或设为开机自启：
#    Docker Desktop → Settings → General → 勾选 Start Docker Desktop when you sign in）
# 2. 数据库容器
docker start multi-doc-mysql
# 3. 开发服务器（在项目目录）
cd /d/MyCode/Multi-document
env -u CODEBUDDY_SAFE_DELETE_BULK_GUARD -u CODEBUDDY_SAFE_DELETE_BULK_STATE_DIR -u CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD npm run dev
```

## 关键信息

| 项 | 值 |
|---|---|
| 前台 | http://localhost:4000 |
| 后台 | http://localhost:4000/admin/login（admin / admin123） |
| 数据库 | 127.0.0.1:**3307**，root / multidoc123，库名 multi_document |
| 数据文件 | Docker 卷持久化，删容器不丢数据；`docker compose -f docker-compose.dev.yml down` 也保留 |

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 页面 500/502，日志报 `pool failed to retrieve a connection` | Docker Desktop 没启动 → 启动它，再跑脚本 |
| `Missing script: "dev"` | 不在项目目录，先 `cd /d/MyCode/Multi-document` |
| 启动时报 safe-delete 错误 | 启动命令必须带那三个 `env -u`（脚本已内置） |
| 启动很慢 | 首次编译 + 删除旧缓存所致，等 1-2 分钟；不要频繁重启 |
| 想彻底清空重来 | `docker compose -f docker-compose.dev.yml down -v` 会**删光数据**，慎用 |

## 两个"根因提醒"

1. **每次重启电脑后，Docker Desktop 需要启动**（设置开机自启可根治），它是数据库的前提。
2. 整个应用打成 Docker 镜像（连代码一起容器化）尚未做，在排期里；现在 Docker 里只有数据库。
